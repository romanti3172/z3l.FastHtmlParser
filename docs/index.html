Scraping code that reads like the page

Typed tags and attributes, and chains that never throw. Prefer XPath? That works too.

  • 1
    Typed and allocation-freeAbout 250 tags and 250 attributes as enums: HTML, SVG, MathML, RSS, Atom, sitemaps.
  • 2
    Null-safe chainsA missing element gives null at the end of the chain, not an exception.
  • 3
    Absolute linksAttributeHref() resolves links against the page URL for you.
  • 4
    XPath 1.0doc.XPath("//div[@class='card']/a") and XPathValues("//a/@href"), compiled and cached.
using z3l.FastHtmlParser;

var doc = new HtmlParser(html, "https://example.com/catalog/");

// first match
var title = doc.Find(HtmlTag.H1).Text();
var price = doc.Find(HtmlTag.Span, cls: "price").Text();

// chains never throw: a missing tag gives null
var phone = doc.Find(HtmlTag.Div, id: "contacts")
               .Find(HtmlTag.A, cls: "phone")
               .AttributeHrefTelephone();

// all matches, links made absolute
foreach (var a in doc.Find(HtmlTag.Div, cls: "gallery")
                     .FindAll(HtmlTag.A))
{
    Console.WriteLine(a.AttributeHref());
}

// or XPath 1.0
var links = doc.XPathValues("//div[@class='gallery']//a/@href");

Everything scraping needs, nothing it doesn't

Fewer CPU cores per crawler, less GC pressure, lower cloud bills.

Fast parsing

One pass, one exact-size list of tags. A 50 KB page parses in about 60 μs.

Zero-allocation matching

Find, FindAll and Is compare spans and enums: searching allocates nothing.

Clean text, real entities

Text() gives visible text; TextLineBreaks() keeps lines and paragraphs. All 2125 HTML5 entities decoded like a browser.

XPath 1.0

All axes, predicates and functions. About 7x faster than HtmlAgilityPack running the same expressions.

XML, RSS, Atom, sitemaps

Documents starting with <?xml are parsed by XML rules, so feeds and sitemaps just work.

Thread-safe, AOT-ready

A parsed document is read-only: query it from any number of threads. Trimming and Native AOT compatible.

What it is not. It builds a flat list of tags, not a full DOM: no CSS selectors, no implicit <tbody>, read-only documents. For extracting data it finds the same elements, texts and attributes as AngleSharp; the test suite checks this on every saved page.
